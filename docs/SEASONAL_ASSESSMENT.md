# Saved seasonal context

New analyses use `seasonal-context-v1`. The farmer selects an intended planting month in My Farms, saved-farm details, or the drawing/GPS analysis flow. The selection is a calendar month, without a planting year. It is not a forecast. Changing months bypasses the location-only duplicate cooldown; repeated identical month/location requests retain normal safeguards.

The backend queries [NASA POWER's monthly point service](https://power.larc.nasa.gov/docs/services/api/temporal/monthly/) for 2005–2024. Each parameter is accepted only with its expected response unit. Temperature (`T2M`, C) and humidity (`RH2M`, %) are averaged over valid values for the selected month. `PRECTOTCORR` must be mm/day: each year's mean daily rate is multiplied by the actual days in that month before monthly totals are averaged. Leap Februaries are included. Annual entries, other months, out-of-window years, fill values, nonfinite values and incompatible units are excluded. Missing observations are never filled with zero.

Each metric records units, source parameter/units, valid years, valid/expected counts, represented period, quality and method. The snapshot records source URL, requested representative point, spatial method, retrieval/capture timestamps and version. This is gridded point context rather than a farm average or measured soil/weather record. Partial results and complete failures have explicit states and limitations.

Five-year annual references, historical selected-month climate, completed 30-day rainfall and current humidity stay separate. No cross-period temperature blend, unequal-window rainfall comparison, seasonal score multiplier or crop reordering is applied. Existing annual factor grades and Random Forest probabilities are unchanged. Legacy calendar weights remain available only as legacy helper code; the new-analysis path does not invoke them. No reviewed local calendar is configured, so the saved calendar state is unavailable and no new In season conclusion is generated.

Provider work runs once per analysis, after polygon samples are merged. Requests use connect/read timeouts of 3/8 seconds without application retries. A process-local LRU holds at most 128 exact-coordinate/month/version entries: 24 hours for complete results and 5 minutes for partial/unavailable results. Snapshots themselves persist in existing `analysis_sessions.result_snapshot` JSONB. Old untyped SQL climate-cache rows are not reused because they lack unit and observation metadata. No schema migration is needed.

Farmer and analyst result views and report consumers share saved snapshot text. Reopening a result does not fetch or recalculate climate. Older records show that seasonal context was not recorded. Historic month/score/decision data is not rewritten. NPK estimates, CAGRO settings, auth and model artifacts are outside this change.
