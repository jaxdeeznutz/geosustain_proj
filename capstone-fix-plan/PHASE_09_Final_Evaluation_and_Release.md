# Phase 9 - Final evaluation, manuscript and release

Dependencies: applicable implementation and acceptance gates from Phases 0-8. Evaluation-instrument preparation, release tooling and manuscript outline work can start earlier; final conclusions must describe the actual evaluated candidate and scientific limits.

## Evaluation and evidence

- Establish the approved ISO/IEC 25010 edition/characteristics, task-based instrument, participants/sample plan, scale, statistical treatment and consent/privacy handling with the responsible adviser/evaluator. Do not invent a respondent count, survey responses or signoff.
- Freeze an identified candidate after functional blockers are resolved. Have the intended farmer, analyst and administrative/technical evaluators perform relevant tasks and collect actual results through authorized arrangements.
- Separate system test success, participant ratings, model classification performance and agricultural validity. Each answers a different question.
- Complete the original applicable QA requirements with actual evidence, preserving initial failures/retests and pending items. Rerun affected journeys when a material model, nutrient, identity or schema change occurs after evaluation.

## Manuscript and diagrams

- Replace Table 15 placeholders with measured test results, and reconcile Table 13 with the exact model experiment records. Include denominators, class support, limitations and the evaluated candidate.
- Add actual user-evaluation results, interpretation, objective-by-objective conclusions, recommendations and remaining scientific limitations.
- Align role diagrams, DFDs/ERD, process descriptions, screenshots and reports with the final reviewed workflow, formal polygon rule, seasonal evidence, spatial statistics, explanation method and administrator controls.
- Preserve modeled/proxy nutrient wording and the actual Phase 8 outcome. Do not change signed objectives merely to remove an unimplemented requirement; document any genuinely approved revision.

## Release and operations

- Build/sign the intended Android release and record package/version, signer identity and checksum. Verify installation/update and the configured API; file existence is not an installation PASS.
- Identify the deployed web build/backend revision and apply controlled migrations/configuration. Verify source/build parity, protected routes, farm analysis, review/notes, export and actual required provider journeys.
- Verify HTTPS production transport, private credential handling, deployment rollback, database backup/restore and a named operational handover. Keep private signing material out of source and evidence.
- Record final owner/adviser/tester acceptance only when actually obtained. If a dataset/provider/device or scientific gate remains open, state the precise limitation in the handover and evaluation result.

## Completion

Produce the final requirement-to-evidence crosswalk, test and evaluation summaries, release manifests, rollback/handover notes and updated manuscript. Complete when the agreed objectives are supported by the implemented/evaluated release or explicitly accepted limitations, with no fabricated evidence or hidden pending gates.
